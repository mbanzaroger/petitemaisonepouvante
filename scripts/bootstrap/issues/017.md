**Hypothèse** : aucun message perdu ni double traitement.

**Critères de succès**
- RabbitMQ déployé dans le cluster (opérateur ou chart), files durables, accusés manuels.
- Publication / consommation testées depuis deux pods ; redémarrage du consommateur sans perte.
- Message en échec répété routé vers la dead-letter queue.
- Rejeu d'un même `eventId` : stock décrémenté une seule fois.

**Alternative à comparer** : Kafka (rejet ou adoption justifié pour le volume du POC).
